        이 프로토타입이 하는 일

        기획서 v0.1의 MVP 범위(4.1) 중, 실제 시설 연동 없이 소프트웨어만으로 먼저 검증할 수 있는 부분을 브라우저 안에서 모두 돌아가게 만든 것입니다. 관제 · 예약 시스템 대신 가상 시설(한결종합병원)과 합성 수요 데이터를 쓰며, 같은 날 · 같은 차량으로 정책을 바꿔 가며 비교합니다. 서버가 없으므로 링크만 있으면 휴대폰에서도 그대로 실행됩니다.

        내비게이션 연동 ETA

        방문객은 도착 시각을 직접 넣지 않습니다. 위치 공유에 동의하면 현재 위치에서 병원까지의 자동차 경로를 내비 경로 API로 계산해, 거리와 실시간 교통이 반영된 소요 시간으로 도착 예정 시각을 잡습니다. 화면을 열어 두면 1분마다 다시 계산하고, 길안내는 선택한 내비 앱(TMAP · 카카오맵 · 네이버 지도)을 딥링크로 엽니다.

        ETA 출처방식오차 σ [가정]
        TMAP 실시간 교통SK open API 자동차 경로안내 (searchOption=0 교통최적) — 서버에 TMAP_APP_KEY 설정 시소요 시간의 8%, 최소 3분
        카카오내비 실시간 교통카카오모빌리티 길찾기 API — TMAP 실패 시 대체소요 시간의 8%, 최소 3분
        교통 패턴 모델직선거리 × 우회 계수, 시간대별 도심 · 간선 평균 속도 — 키가 없거나 외부 API 장애 시, 그리고 서버 없는 데모소요 시간의 15%, 최소 4분
        내비 파트너 웹훅 (Phase 2)내비 앱이 길안내 중 ETA를 서버로 직접 보냄 (POST /v1/partners/{provider}/eta, HMAC 서명)3분

        한계: 웹 화면에서 TMAP 앱 안의 ETA를 직접 읽을 수는 없습니다. 지금은 같은 TMAP 경로 엔진을 API로 호출하는 방식이며, 방문객이 내비 앱으로 넘어가 이 화면이 백그라운드로 가면 갱신이 멈추고 마지막 계산값을 씁니다. 길안내 중 끊김 없는 ETA는 파트너 웹훅(기획서 4.1 Phase 2)으로 해결합니다.

        백엔드 API (FastAPI)

        레포의 backend/에 부록 B의 핵심 API를 구현했습니다. 배정 엔진은 이 화면의 engine.js와 같은 비용 함수를 Python으로 옮긴 것이고, 테스트가 두 구현의 비용 표 · 슬롯 순위 · 교통 모델 값이 같은지 교차 검증합니다. 서버 주소를 config.js에 넣거나 주소 뒤에 ?api=서버주소를 붙이면 방문객 화면이 서버 모드로 바뀝니다.
